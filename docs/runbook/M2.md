# madc M2 runbook

*Operator's guide to the M2 build ("the room: multi-seat work + evidence schema v2"). The mock conformance path needs no API key and no network (`madc doctor --init`, two-seat handoff, `madc room`, and `madc decisions ls` complete in under 15 seconds on a clean machine).*

Every `madc …` below means `node packages/cli/src/bin.ts …` run from the repo root after `npm ci` (or `bun`). Everything madc keeps lives in `$MADC_HOME` (default `~/.madc`). See [M0.md](M0.md) for install/session basics and [M1.md](M1.md) for lanes and keychain setup.

## 1. Seed a room

Initialize `$MADC_HOME` and verify health:

```sh
madc doctor --init
```

To enable multi-seat handoffs and worktree isolation on a v2 seat in `$MADC_HOME/seats/<seatId>.json`:

- Set `"handoffs": { "enabled": true, "targets": ["<targetSeatId>"] }` (exact seat id match; self-handoff is allowed without a list entry per `D-445`).
- Set `"worktree": true` (opt-in per seat, `D-M2-2`) so threads on that seat open in an engine-created detached git worktree at `$MADC_HOME/worktrees/<threadId>`.

## 2. Run two seats in parallel (isolated worktrees)

When two threads open on `worktree: true` seats against the same git repository `cwd`:

- Each thread receives its own detached worktree at `$MADC_HOME/worktrees/<threadId>` (`session.open.worktree` records `topLevel`, normalized `remote`, and `head`).
- Neither tree contains the other's uncommitted files, and the repo's primary working tree is never used as a seat worktree.
- Vendor agents (`claude-code`, `codex`, `grok-build` via ACP) are spawned with `{ cwd }` set to the thread's worktree.
- On close, M2 leaves every worktree on disk (`D-M2-4`) and records `session.close.worktree.head`. Dirty worktrees are never removed (`removeSeatWorktree` refuses and names the dirty path).

## 3. Handoff chain and brief delivery

1. A source seat hands work off via JSON-RPC `thread/handoff` `{ threadId, targetSeatId, brief, turnId }`.
2. The engine appends `handoff.out` (hash `H`), opens the target thread citing `H` in `session.open.handoff` (creating the target's own worktree if the target seat has `worktree: true`), reads back the target's genesis hash `G`, and appends `handoff.link` (`G`) on the source.
3. On the target thread's first `turn/start`, the engine prepends the pinned brief once (`briefServed` marker recorded); subsequent turns never re-deliver it, and the source file remains byte-identical.

## 4. Inspect the room and answer decisions

```sh
madc room [--json]          # per-thread seat, chain, handoff, worktree, open decisions, findings
madc decisions ls [--json]  # open Founder decisions across all verified threads
madc doctor [--json]        # includes the `room` row; exits non-zero on any FAIL, 0 on WARN-only
```

To resolve an open decision via JSON-RPC, call `decision/resolve` `{ threadId, decisionId, choice }` (`"accepted-default"` or `"custom"` with `resolution`). Resolutions append `founderDecision.resolved` and never edit prior lines.

## 5. Recorded residual risks

- **Vendor `cwd` placement is not a sandbox (Criterion C).** Vendor adapters (`claude-code`, `codex`, `acp-client`) are started in the thread's worktree `cwd`, but madc does not sandbox the vendor agent's own file tools.
- **No per-seat rate cap in M2 (`D-M2-9`).** Ruled by the Founder on 2026-11-23 (`"No rate cap in M2."`): parallel Claude Code seats have no engine-enforced per-seat rate limit in M2; deferred past M2.
- **Worktrees remain on disk (`D-M2-4`).** Seat worktrees are left on disk at close so uncommitted work is never lost; cleanup is a separate, explicitly authorized step.
- **Path-pinned `repoAllow` inside a worktree.** Because a seat worktree's `topLevel` is `$MADC_HOME/worktrees/<threadId>`, path-pinned `repoAllow` entries matching the primary checkout deny `repo-not-allowed` inside the worktree; remote-pinned `repoAllow` entries match `origin` normally.
