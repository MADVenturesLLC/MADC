# madc M0 runbook

Operator's guide to the M0 build: install, health-check, run one turn, and read the
session record. Everything below runs locally; the mock paths need no keys and no
network. Floors: **node ≥ 22.19** or **bun ≥ 1.2** (the repo's `engines` field).

## 1. Install

```sh
git clone https://github.com/MADVenturesLLC/MADC.git
cd MADC
npm install
```

There is no publish, no `npm link`, no global install in M0. You invoke the CLI
straight from the source tree, with either runtime:

```sh
node packages/cli/src/bin.ts --version
bun  packages/cli/src/bin.ts --version
```

Both print `madc 0.0.0 (protocol madc-m0/1)`. Every `madc …` command below means
`node packages/cli/src/bin.ts …` (swap `node` for `bun` freely; the CI matrix runs
the full test suite on both).

## 2. `madc doctor`

```sh
node packages/cli/src/bin.ts doctor
```

Doctor is read-only: it creates, seeds, locks and appends nothing. Rows print as
each check finishes; the last line is `RESULT <f> FAIL · <w> WARN · <s> SKIP …`,
and the exit code is 0 when nothing FAILs (WARN and SKIP never fail doctor).

| Row | What it checks |
| --- | --- |
| `runtime` | Your node/bun version meets the floor. |
| `engine` | Spawns the engine against a throwaway temp home, handshakes `madc-m0/1`, expects exit 0. Never touches your real home. |
| `home` | The resolved `$MADC_HOME` path (absolute, and where it came from). WARN `not initialized` if missing. |
| `seat` | The `madc-default` seat file parses; evidence is its path plus a sha256 prefix. |
| `session` | The hash chain of the most recent session verifies (see §6). SKIP when there are no sessions yet. |
| `locks` | Read-only survey of `sessions/*.lock`: owner pid alive, no orphaned reclaim files. Never prints a lock token, never repairs anything. |
| `registry` | The provider catalog loads; prints entry counts by status and which backings are wired. |
| `cred.kimi-code` | Only whether `KIMI_API_KEY` is present in the env — never its value. WARN when unset. |
| `bin.claude`, `bin.codex` | PATH lookup only (never executes the binary); SKIP either way. The `adapter not built (A5/A6)` suffix is frozen row text from the CLI act; the vendor backings in fact ship with acts A5/A6 — see §4 and §5. |

First run — seed the default seat through the engine itself (the CLI never writes
seat bytes):

```sh
node packages/cli/src/bin.ts doctor --init
```

`--init` prints an `INIT seeded <path>` row (or `INIT already present`, byte-identical
sha256) and then the normal report. Running plain `doctor` first is safe: it just
WARNs `not initialized`.

## 3. Kimi Code path

### Mock (no key, no network)

The test harness ships a fake engine, `packages/engine/src/testing/kimi-fake-engine.ts`:
the real provider agent over an in-process fake transport whose base URL is a
`.invalid` host — it cannot reach the network. The engine still requires *a* key to
be present (preflight honesty), so pass any dummy string. Point the CLI's test
launcher at the fixture via `MADC_TEST_ENGINE_ENTRY`:

```sh
MADC_HOME=/tmp/madc-demo KIMI_API_KEY=test-fake-key \
  MADC_TEST_ENGINE_ENTRY=packages/engine/src/testing/kimi-fake-engine.ts \
  node packages/cli/src/testing/cli-launcher.ts -p "say hi"
```

You get the fake reply on stdout and a receipt on stderr: turn status, the
`requested → served` model line, and the session path with `chain VERIFIED`:

```
Hello from fake Kimi
─ receipt ─────────────────────────────────────────────
 turn     COMPLETED            turn_…                   0.1s
 model    kimi-coding/kimi-for-coding → kimi-for-coding   (kimi-code)
 session  /tmp/madc-demo/sessions/thr_….jsonl
          seq 6 · head add47bead640 · chain VERIFIED
 exit     0
```

Add `--json` for the machine-readable form (exactly one JSON object on stdout).
This is the same path CI exercises in `packages/engine/src/m0-matrix.test.ts`.

### Live (optional, needs your key)

```sh
KIMI_API_KEY=<your key> node packages/cli/src/bin.ts -p "say hi"
```

The production CLI (`packages/cli/src/bin.ts`) always spawns the real engine. Per
the registry, the Kimi Code seat is `allowed-direct` with `honest-ua-required`: madc
identifies itself to the provider as itself (`madc/0.0.0 (pi-ai/…)`) and never
impersonates a vendor client. Without `KIMI_API_KEY`, turns refuse with
`-32008 no-credentials` before any request is sent.

## 4. Claude Code (optional)

Requires the **unmodified** `claude` binary on PATH (any install you already have;
madc never forks, patches, or re-configures it, and the child inherits your env and
finds its own auth exactly as when you run `claude` by hand).

Seat it: copy `$MADC_HOME/seats/madc-default.json` to `$MADC_HOME/seats/claude.json`
and change three fields — `id: "claude"`, `preferredBacking: "claude-code"`, and
`pinnedModel` to a vendor model name such as `claude-sonnet-4-5`. Then:

```sh
node packages/cli/src/bin.ts -p "say hi" -s claude
```

The adapter spawns `claude -p <prompt> --output-format json --model <pinnedModel>`
(the documented print mode), captures the one JSON result at exit, and emits it as
the turn's agent message with a `servedModel` receipt. When `claude` is not on PATH,
the turn refuses with `-32008 binary-missing` — nothing is faked. In CI, fake-child
tests cover this path and the live case is skipped when the binary is absent.

## 5. Codex (optional)

Requires the **unmodified** `codex` binary on PATH. Auth is whatever Codex itself
documents — ChatGPT sign-in or an API key — carried by the unmodified binary; madc
never reads, logs, proxies, or rewrites Codex credentials or its session files.

Seat it the same way: `id: "codex"`, `preferredBacking: "codex"`, `pinnedModel` a
vendor model name such as `gpt-5.1-codex`, then:

```sh
node packages/cli/src/bin.ts -p "say hi" -s codex
```

The adapter drives `codex app-server` (Codex's documented embed path: JSON-RPC over
stdio) — one child per turn: `initialize` → `thread/start` (your pinned model,
`approvalPolicy: never`, `ephemeral: true` so no vendor thread is materialized under
your `$CODEX_HOME`) → `turn/start` → streamed deltas → `turn/completed`. When `codex`
is not on PATH the turn refuses with `-32008 binary-missing`. CI covers this path
with a fixture app-server child; the optional live smoke test runs only when you set
`MADC_TEST_CODEX_LIVE_MODEL` to a model your Codex auth serves.

## 6. Where session files live

Everything madc persists lives under **`$MADC_HOME`** (default `~/.madc`):

```
$MADC_HOME/
  seats/madc-default.json      # named seats (doctor --init seeds the default)
  sessions/<threadId>.jsonl    # one hash-chained record per thread
  sessions/<threadId>.lock     # owner pid + start time + token, while an engine holds the thread
  memory/                      # seat memory files
```

Each session JSONL line is an event — `session.open`, `turn.start`, `item`,
`servedModel`, `turn.end` — carrying `seq` and `prevHash`/`hash`, so any edit,
reorder, or truncation breaks the chain. Locks are advisory ownership records; doctor
surveys them read-only and never deletes them (repair arrives in M1).

To verify a chain, run `madc doctor` (§2): the `session` row re-reads and verifies
the latest session and PASSes with `<threadId> · <n> events · head <12 hex>`. A FAIL
as `torn tail …` means crash residue, not tampering; `integrity: line N …` means the
bytes were altered. The one-shot receipt prints the same head hash, so you can
cross-check receipt against doctor. Tamper with a line and both will tell you — the
engine fails closed and never modifies the file itself.
