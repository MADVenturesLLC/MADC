## 1. Grok Build (optional live step)

CI never runs this step. It uses your own Grok Build sign-in and may use your plan's quota.

**Requires** the **unmodified** `grok` binary on PATH (checked against grok 1.0.44), signed in
by Grok Build itself: either `grok login` (your SuperGrok / X Premium+ login, held by Grok Build
only) or `XAI_API_KEY` exported in the shell that runs madc (the API-key class). madc never reads
`~/.grok` or any Grok credential file, never reads the key's value (it only checks whether
`XAI_API_KEY` is set, to pick the matching ACP auth method), never hands Grok the `xai-api`
keychain key, and never uses pi-ai's xAI OAuth.

**Seat it:** copy `$MADC_HOME/seats/madc-default.json` to `$MADC_HOME/seats/grok.json` and change
three fields: `id: "grok"`, `preferredBacking: "grok-build"`, and `pinnedModel` set to a model id
that `grok models` lists for your sign-in. Then:

```sh
node packages/cli/src/bin.ts -p "Reply with the word ok." -s grok
```

One child per turn: `grok --no-auto-update agent --no-leader --model=<pinnedModel> stdio`, driven
over ACP (`initialize` → `authenticate` with `_meta.headless` → `session/new` → `session/prompt`).
Check the `servedModel` receipt: `vendorReported: true` only if Grok reported its model through
ACP; otherwise the receipt records your `pinnedModel` with `vendorReported: false`. A protocol
`turn/interrupt` sends ACP `session/cancel` to Grok, then stops the child.

**Adapter-only live check** (no engine, fixed trivial prompt, answer never printed):

```sh
MADC_TEST_GROK_LIVE_MODEL=<model id from `grok models`> \
  node --test packages/adapters/src/vendor/grok-build.test.ts
```

Without `grok` on PATH or without `MADC_TEST_GROK_LIVE_MODEL`, the live test is skipped.

**Failures you may see:**

| Result | Meaning |
| --- | --- |
| `-32008 binary-missing` at `turn/start` | `grok` is not on PATH. |
| turn `failed`, `-32008 no-credentials` | Grok Build offered no usable sign-in or refused it. Run `grok login`, or export `XAI_API_KEY`. |
| `-32006` at `turn/start` | `pinnedModel` is empty or not a plain model id (for example it starts with `-`). |

**Approval posture:** madc never passes `--always-approve`. If Grok asks for permission over ACP,
madc refuses (M1 has no approval surface). madc cannot see or limit tool use that Grok runs
without asking; Grok's own permission settings govern that.
